# 读一张机械图纸然后建出来

这张纸上有两个东西：**标注**（数字，唯一可信）和**图形**（线，只说明形状和归属）。
把两者混在一起是绝大多数错误建模的开头。

读图的目标不是「把尺寸抄下来」，而是产出一张能直接拿去 `model action="plan"` 的
**尺寸表**：每个尺寸带公差、视图、锚点、对应的模型轴/基准面；每个基准带名字与用途。
只有数字、没有归属的清单，不算读完图。

## 一、输出格式：必须交这张表

读图结束先交这张表（Markdown 表格即可），再谈建模：

| # | 尺寸/特征 | 标注值 | 公差 | 视图 | 锚点（图上指谁） | 模型轴 / 基准面 | 来源 | 落到哪个特征 |
|---|---|---|---|---|---|---|---|---|
| 1 | 总长 L | `<值>` | `<± / H7 / 未注>` | 主视 | 左端面 ↔ 右端面 | X（plane 1） | 标注 | 底板拉伸 |
| 2 | 孔径 Ød | `<值>` | `<H7 等>` | 俯视 | 圆心 + 两条中心线 | plane 1，草图层 | 标注 | 孔组切除 |
| 3 | 孔心距边 | `<值>` | `<±>` | 俯视 | 孔心 ↔ 板边 | X/Z | 标注/派生 | 草图点-线尺寸 |
| 4 | 基准 A | — | — | 主视 | 底面 | plane 1（反向） | 基准符号 | 装配/形位公差引用 |

- **公差列不能空**：直接标注的公差照抄；没有直接标注的写未注公差依据（标题栏/技术要求里的
  标准与等级）；确实没有依据的写「未注 / 待确认」，不要默认零公差。
- **视图列**写清这条尺寸属于哪个视图；同一尺寸在两个视图出现且数值不同，是图纸矛盾，停下来问。
- **锚点**必须能对上模型里的一个几何对象（某根轴线、某张面、某条边）。说不清它指着谁的标注，
  就是**还没读懂的标注**，不能拿去建模。
- **模型轴/基准面**写这条尺寸落到哪个世界轴或哪张基准面；这一步是把图纸坐标翻译成模型坐标。
- **来源**只允许三种：`标注`、`派生`（由标注算出来，必须写算式）、`量取`（像素标定，必须写标定依据）。
- **落到哪个特征**写草图/拉伸/切除/孔组/圆角等；一条尺寸落不到特征，说明图还没读完整。

## 二、定投影法，再定视图归属

- **第一角法**：俯视图在**主视图下方**，左视图在**主视图右方**，右视图在左方。
- **第三角法**：俯视图在**上方**，左视图在**左方**，右视图在右方。
- 国内图纸绝大多数是第一角法，ISO 图框上第一角法的符号是「锥台小头在左」。

认错的代价：左右反、前后反，所有非对称特征全装错位。认不出来的话先找图框里的符号，
或者拿一个明显不对称的特征（比如只有一侧有凹槽）验证一次。

## 三、视图 → 模型姿态映射

投影法决定「视图摆在哪一侧」，姿态映射决定「图纸方向对应模型哪个轴」。两者不能混为一谈。

SOLIDWORKS 是 Y 向上，三张基准面与图纸视图的对应关系：

| 图纸视图 | 模型观察方向 | 草图基准面 | 草图 u / v | 深度正方向 |
|---|---|---|---|---|
| 主视图（前视） | 从 +Z 看 | plane 0 前视 | +X / +Y | −Z |
| 俯视图（上视） | 从 +Y 看 | plane 1 上视 | +X / **−Z** | −Y |
| 左视图 | 从 −X 看 | plane 2 右视 | −Z / +Y | −X |

- 主视图上的「上」是 +Y，俯视图上的「上」是 −Z（世界 z 写成草图 v 要变号）。
- 如果图纸把主视图旋转了（图框上有旋转角或视图带角度），先记下旋转，再套上表；
  不要拿「看起来水平」当 +X。
- 映射对不对，用 `inspect action="bodies"` 的包围盒验一次：三个方向的长短要与三视图对得上。
- **水平底板画在 plane 1，竖直筋板/凸台画在 plane 0**；画反了零件「躺着」，尺寸却全对。

## 四、把标注变成「带锚点、带公差的数字」

一条标注不能只记「Ø<值>」，要记成：

```
{ value, kind: 'diameter' | 'length' | 'radius' | 'angle',
  tolerance: { type: 'symmetric' | 'deviation' | 'fit' | 'general', ... },
  anchor, view, orientation: { axis | plane }, datum: '<A/B/C 或 null>',
  derived: false, chain: null }
```

- **尺寸链**：图上一串数字能凑成总长时，先自己把加法算一遍。算不平就说明其中某个数不是
  相邻两段之和 —— 这类加减是判断「这个标注到底指什么」最硬的证据。
- **派生量**（图纸没标，但可以由标出来的算）：例如孔心高度 = 总高 − 半径 − 板厚。
  派生量要标 `derived: true` 并写算式，这样后面模型不对时能分清是读错了还是算错了。
- **公差**：
  - 直接公差（`Ø<基本尺寸> H7`、`<基本尺寸> +<上偏差>/-<下偏差>`、`<基本尺寸>±<偏差>`）照抄，
    并记是孔还是轴（H 是基孔制孔）；
  - 未注公差按标题栏/技术要求的标准与等级查表，不按「看着差不多」取；
  - 形位公差（∥ ⊥ ⌖ ◎）连同基准字母一起记，它是验收关系与装配约束的来源；
  - 建模用**名义尺寸**；验收时按公差带判断，不要把中值当唯一真值。

## 五、基准（datums）：图框里的 A/B/C

图纸上的基准符号不是装饰：形位公差、装配约束、位置度都指向它。

- 每个基准记一行：字母、基准要素（面/轴/点）、对应模型对象、用途（哪几条形位公差引用它）。
- 读图完成后用原生基准把它落下来（名字与图纸一致，方便验收引用；先
  `catalog action="activate" capability="datum"`）：

```
datum action="create" designId="<id>" name="A" kind="plane"
                     source={ type:"faceEdge", face:"<底面 persistentId>" }
datum action="list" designId="<id>"
```

- 装配定位用 `placement:"datum:<name>"` 引用，不依赖容易变的面序。
- 基准与图纸对不上（文件里有、模型里没有）会标 stale：先重建基准，别继续拿它验收。
- 基准顺序不要自己改（例如把 A 底面当成 B 侧面）；改了之后所有形位公差都失去意义。

## 六、从标注推到特征，四类各写一行

| 类别 | 图纸依据 → 特征 |
| --- | --- |
| 外轮廓 | 长、宽、板厚、四角 R → 底板 roundedRect 拉伸 |
| 切口 | 槽宽、槽深、弧心距、端部 R → 每处槽一个矩形切除 + 一个圆弧切除 |
| 孔 | 孔径、孔数、孔心位置、公差 → 通孔切除；孔心高度用「总高 − 半径」或图上直接标注，不猜 |
| 支承与筋 | 外圆直径与顶部 R → 支承体外廓（顶面 = 轴线高 + R）；筋板走向与厚度按标注 |

**同一张图纸上的数要能互相验算**。算不平的地方就是读错了：先怀疑自己，再怀疑图纸。

## 七、每一个标注都要有一条能跑的数字核对

建模完的工作不是「看起来像」，是：

```json
{ "name": "主孔轴线到底面 <标注值>", "measure": "distance",
  "args": { "a": { "plane": "minY" }, "b": { "axis": { "diameter": "<孔径>" } } },
  "expect": "<标注值>", "tol": "<按公差带定>" }
```

- 每条 `expect.checks` 对应尺寸表里的一行；数不出来就说明那个特征没建出来。
- 体积、包围盒只放进 `auxiliary`。**体积对上只说明画的是一个实心件**，
  说明不了孔在正确的高度。用体积当验收的后果是：形状全错但数字看起来对。
- 量凸台/外圆这类实体圆柱要传 `"hole": false`（默认只找孔）。
- 复核时先看 `inspect action="sketch"` 的几何（段数、闭合、半径），再看体积。
- 装配件的界面尺寸（配合面、同轴度）用 `assembly_inspect action="assemblyFaces"` /
  `"mates"` 验（先 `catalog action="activate" capability="assembly_inspect"`），
  不要拿单个零件的包围盒代替。

## 八、先量像素比例，目的是证明它不能用来量尺寸

用 `inspect action="figure"` 的 `op="crop"` 配 `grid`，网格线标签是**源图像素坐标**。
同一张图上每个视图的横、纵各量一条已知标注，算出 px/mm —— 不同视图的比值常常差一倍。
**结论不是「找个平均比例」，是「像素永远不能当长度用」。**

像素只回答两件事：这个标注的尺寸界线指着哪条边；这条边属于哪个视图。
当作图软件导出的矢量图（PDF/PNG 无损）比例才可能一致，但也要先验一遍再相信。

## 九、未标注尺寸：自己标定量，**不许先问人**

图纸上没标出来的尺寸，先用已标注尺寸标定量出来：

1. `inspect action="figure"`，`op="crop"` 放大到能看清这条边和一条**有标注**的边，`grid` 标像素；
2. 用那条已知标注算 `mm/px`（同一视图内标定，跨视图比例常常差一倍）；
3. 按它换算你要的那条尺寸，并在报告里写「按量取 `<值>`（标定 `<mm/px>`）」；
4. 把这个值写进 `assumptions` 并标 `derived`，随交付一起标出。

只有两种情况可以问人：

- ① 图纸与文字要求**互相矛盾**（例如图注与图上标注对不上）；
- ② 两种读法的体积差 **>5%** 且图纸本身无法裁决（例如整块鞍座 vs 两片筋）。

问的时候**必须附上你自己算出的候选值与依据**：两种读法各得多少体积、差多少、图上哪一处
看不到。把「我已经算过」摆出来，用户只需要选 A 或 B；不要问「你看这条尺寸是多少」。

## 十、歧义要问，但只问「读法」，不问「数字」

尺寸类的歧义按第九节自己量。真正值得问的是**结构判读**，而且问之前先把两种读法
各出一份 plan/体积对比（上面 ② 的门槛）：形状两可、但两种读法可以自动算出差别时，
用数字把问题压缩成一个二选一。
